# ファイル名の文字コードとパスの扱い


日本語（全角）のファイル名・フォルダー名をそのまま扱えます。濁点・半濁点は合成済み（NFC）でも結合文字（NFD、macOSの正規化形）でも、半角カタカナ、絵文字、空白や記号を含む名前でも同様です。

内部ではパスを文字列に変換せず、OSのファイル名表現のまま受け渡します（`OsString` / `OsStr`）。Windowsでは UTF-16、Linux/macOSではバイト列として扱うため、**UTF-8ではないファイル名**（古い環境から持ち込んだShift_JIS名など）でもエラーにならず処理できます。公式エンジンには常に `input.wav` という固定名で渡すので、エンジン側の文字コードの扱いに影響されません。

なお、UTF-8でないファイル名が実際に存在しうるのはLinuxなど、ファイル名を任意のバイト列として扱うファイルシステムだけです。macOSのAPFSは妥当なUTF-8しか受け付けず（`Illegal byte sequence` で作成そのものが失敗）、WindowsのファイルシステムはUTF-16のため、これらの環境ではこの状況が発生しません。該当のテストは、ファイルシステムが受け付けない場合に理由を示して検査を飛ばします。

引数はシェルを介さず個別の値として子プロセスへ渡すため、空白・記号・引用符の有無で挙動が変わりません。パスの書き方（絶対・相対・`./`・`..`）が違っても同じファイルとして扱い、入力と同じファイルを別の書き方で出力先に指定した場合も上書きせずに断ります。

**どのOSでも持ち運べる出力名だけを受け付けます。** Windowsの予約デバイス名（`NUL`、`CON`、`COM1` など。拡張子を付けても同じ扱いです）、末尾の空白や `.`、`< > : " | ? *` を含む名前は、LinuxやmacOSで実行した場合も断ります。予約名に書くと内容がどこにも残らないまま成功したように見え、末尾の空白や点はWindowsが黙って削って別名のファイルになるためです。日本語・全角記号・絵文字はそのまま通ります。

**PowerShell での注意（Windows PowerShell 5.1）:** 画面に直接表示する分には日本語が正しく出ますが、出力をパイプやリダイレクトで受けると、PowerShell 5.1 は既定でOSのコードページ（日本語環境では932）として解釈するため文字化けします。次のいずれかで解消します。

```powershell
[Console]::OutputEncoding = [Text.Encoding]::UTF8   # 5.1 で一時的に
```

PowerShell 7 以降は既定が UTF-8 のため、この対処は不要です。
