# ノイズ除去の効果（実測値）

測定日: 2026-09-05 / DeepFilterNet v0.5.6

測定環境は Linux x86_64（musl ビルドのエンジン）です。Windows でも同じ結果になることは[プラットフォーム間の一致](#プラットフォーム間の一致)で確認しています。

## 使った音源

リポジトリ同梱の `samples/clean.wav` と `samples/noisy.wav` です。クローンすればそのまま再現できます。

| | 値 |
|---|---|
| 長さ | 6.736 秒（323,307 フレーム、48 kHz モノラル PCM16） |
| 処理前 SNR | **-5.00 dB**（雑音のほうが音声より大きい） |
| 無音区間 | 108,915 サンプル（33.7%） |
| 声の区間 | 66,990 サンプル（20.7%） |

`noisy = clean + 雑音` で長さと時間位置が完全に一致しています。この関係が成り立たないと差分による測定はできません。

## 結果（既定設定）

| 指標 | 処理前 | 処理後 | 差 |
|---|---|---|---|
| SNR | -5.00 dB | 11.09 dB | **+16.09 dB** |
| 無音区間のノイズ床（RMS） | 3310.8 | 224.8 | **-23.36 dB** |
| 残留ノイズのエネルギー | 基準 | — | **-16.09 dB（97.5% 減）** |
| 声の区間のエネルギー | 基準 | — | -0.82 dB |
| 長さ | 323,307 | 323,307 | 変化なし |
| 時間のずれ | — | — | **0 サンプル** |

**雑音が音声より大きい状態から、音声のほうが 11 dB 大きい状態まで改善しています。** 無音区間の雑音は振幅で約 93% 落ち、その一方で声の区間のエネルギーはほぼ変わっていません（-0.82 dB）。

## 設定ごとの比較

| 設定 | SNR | 改善 | ノイズ床 | 声の増減 |
|---|---|---|---|---|
| **既定（`-a 100`）** | **11.09 dB** | **+16.09 dB** | -23.36 dB | -0.82 dB |
| `-a 100 --pf` | 11.04 dB | +16.04 dB | **-23.73 dB** | -0.84 dB |
| `-a 60` | 11.09 dB | +16.09 dB | -23.34 dB | -0.82 dB |
| `-a 60 --pf` | 11.04 dB | +16.04 dB | -23.72 dB | -0.84 dB |
| `-a 30` | 10.90 dB | +15.90 dB | -22.13 dB | -0.78 dB |
| `-a 20 --pf` | 9.55 dB | +14.55 dB | -18.37 dB | -0.69 dB |

読み取れること:

- **既定のままで十分です。** `-a` は抑制の上限を決める値で、100 と 60 は同じ結果になります。この音源では 60 dB を超える抑制が必要な場面がなく、上限に達していないためです。
- **`-a` を絞ると効果が落ちます。** 30 で -0.19 dB、20 で -1.54 dB。雑音を残したい理由がなければ下げる意味はありません。
- **`--pf` は雑音をより落とす代わりに SNR がわずかに下がります**（ノイズ床 -23.73 dB に対し SNR は -0.05 dB）。無音部分の静けさを優先するなら有効、元の声への忠実さを優先するなら不要、という使い分けになります。
- どの設定でも**声の区間のエネルギーは -0.8 dB 前後**で、雑音の落ち方（-18〜-24 dB）とは桁が違います。声を削らずに雑音だけを落とせています。

## プラットフォーム間の一致

同じ音源・同じパディング済み中間ファイルを、Linux 版エンジン（musl ビルド）と Windows 版エンジン（MSVC ビルド）でそれぞれ処理して比較しました。

| | 処理後 SNR | 改善 |
|---|---|---|
| Linux x86_64（musl） | 11.09 dB | +16.09 dB |
| Windows x86_64（MSVC） | 11.09 dB | +16.09 dB |

**改善幅は完全に一致**します。サンプル単位では 323,307 中 323,237（99.98%）が完全一致し、**残りも差は 1 LSB**（ピーク振幅の 0.006%）でした。エンジンのプラットフォーム別ビルドにおける浮動小数点演算の差によるもので、聴感に影響する大きさではありません。

**どの OS で処理しても同じ結果が得られる**と考えて差し支えありません。

## 測定方法

```
SNR      = 10·log10( Σclean² / Σ(signal−clean)² )
ノイズ床  = clean の振幅が 200 未満の区間での signal の RMS
声の増減  = clean の振幅が 2000 以上の区間でのエネルギー比
時間ずれ  = 相互相関が最大になるオフセット
```

残差 `signal − clean` には「取り切れなかった雑音」だけでなく「モデルによる声の変化」も含まれます。したがって SNR の改善幅は、雑音除去の性能を下から見積もった値になります。

## 再現方法

```bash
cd cli
cargo test --test noise_reduction -- --nocapture
```

手元の音源で測る場合は環境変数で指定します。

```bash
DEEPFILTER_CLEAN=/path/to/clean.wav DEEPFILTER_NOISY=/path/to/noisy.wav \
  cargo test --test noise_reduction -- --nocapture
```

## テストの合格条件について

`cli/tests/noise_reduction.rs` の閾値（SNR 改善 1.5 dB 以上、ノイズ床 3 dB 以上の低下）は、上の実測値より**大幅に緩く**設定してあります。これは、環境変数で任意の音源を渡せる設計のためです。同梱音源での実測は閾値を 10 倍以上上回っています。

同梱音源に限れば、この差が縮まったときは性能の劣化を疑ってください。
